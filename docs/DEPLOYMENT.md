# Публикация MVP

Цель: приватный репозиторий GitHub и один Render Web Service. PRD и список оставшихся доработок: [PRD.md](PRD.md). Фактически проверенное: [VALIDATION.md](VALIDATION.md).

## 1. Исходники

В корне проекта выполнить `npm ci`, `npm run check`, `npm test`. Папка `node_modules` и секреты не должны попадать в git. Полный словарь пока не подключён.

Если проект ещё не является git-репозиторием:

```bash
git init -b main
git add .
git commit -m "Add Hebrew Word Duel MVP and product requirements"
```

Использовать собственную настроенную git-идентичность. С GitHub CLI и подтверждённой учётной записью можно создать приватный репозиторий:

```bash
gh repo create hebrew-word-duel --private --source=. --remote=origin --push
```

В этой сессии удалённый репозиторий не создан; URL репозитория не назначен.

## 2. Render

В выбранном рабочем пространстве создать **Web Service** из этого репозитория. Если приватный репозиторий не виден, предоставить GitHub-интеграции Render доступ к нему.

| Параметр | Значение |
|---|---|
| Runtime | Node |
| Build command | `npm ci` |
| Start command | `npm start` |
| Health check | `/health` |
| Instance plan | Free для закрытого теста |
| Количество процессов/копий | 1 |
| Node | 22, как в `render.yaml` |
| Порт | Передаваемый Render `PORT`; bind `0.0.0.0` |
| WebSocket | `wss://<service-host>/ws` |

Альтернатива ручной настройке — Blueprint из существующего `render.yaml`. Не создавать два отдельных сервиса для HTTP и WebSocket. Не добавлять базу данных или платный диск на этом этапе.

## 3. Проверка после деплоя

Дождаться статуса `live`. Проверить `/health`, затем создать комнату в одном браузере, открыть ссылку в другом и выполнить ход. Проверить джокер, запрет повтора, историю и возврат после обновления страницы. Просмотреть логи на ошибки.

Сервис Free может засыпать после отсутствия трафика и медленно просыпаться. Любой перезапуск уничтожает текущие комнаты. Закрытому пилоту нужно явно показывать это ограничение и тестовый статус словаря.
